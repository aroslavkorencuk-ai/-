1) Сможет ли прочитать notes.txt? — Да, сможет (при условии, что у самого файла notes.txt есть права на чтение для её группы или для всех).
 Сможет ли выполнить ls в этом каталоге? — Нет, не сможет. Команда ls выдаст ошибку вроде "Permission denied".
Объяснение (разница между r и x на каталогах):
В Linux право r (read) на каталог разрешает только чтение содержимого (списка файлов) внутри него (то, что делает команда ls).
Право x (execute / search) на каталог разрешает проход сквозь него (обращение к файлам по известному пути). Если у вас есть право x на каталог, но нет r, вы не можете «заглянуть внутрь» каталога (посмотреть список файлов), однако можете обратиться к конкретному файлу внутри него, если точно знаете его имя и путь к нему (например, открыть /project/notes.txt). 

2) Какая группа будет у копии? — У копии файла в домашнем каталоге alice будет группа alice (основная группа пользователя alice), а не developers.
Почему setgid здесь не работает? — Потому что файл создается заново процессом пользователя alice внутри её собственного домашнего каталога, а не в каталоге с установленным setgid.

3) Связка nologin + точечное правило sudo ограничивает ущерб гораздо сильнее по следующим причинам:
• Блокировка интерактивного входа
•  Принцип наименьших привилегий
• Группа sudo обычно дает права ALL

4)  Дополнительные возможности для webapp: Нет, самому владельцу (webapp) права 777 не дают абсолютно никаких преимуществ по сравнению с 700. В первой триаде (права владельца) у него и так был полный доступ rwx.
Опасность 777: Эти права опасны из-за второй и третьей триады вместе. 
 Кому конкретно открылся доступ:
Группе developers (вторая триада): Теперь любой участник этой группы может читать конфиг, изменять его или удалять. При правах 700 у них не было доступа вообще.
Всем остальным ("others", третья триада): Теперь любой пользователь или системный процесс в системе (даже самый непривилегированный) может прочитать config.yml.
В чем главная угроза: В файлах .yml часто хранятся пароли от баз данных, API-ключи и другие секреты. Установив 777, вы сделали эти секреты публичными для всех пользователей сервера. Любой "сосед" по системе теперь может украсть данные или саботировать работу приложения, изменив настройки.
